## 六、我能从这个项目学到什么（知识地图）

按"求职有用度"从前往后排，每一项都对应本项目真实文件：

### ① 提示词工程（Prompt Engineering）—— 最贴近"AI 应用"核心
- **学到**：角色设定、多轮对话状态（问姓记称呼）、"内心 OS/动作提示"让数字人有表演感、考模式出题+判分容错规则。
- **对应文件**：`Dify迎宾交互提示词.md`、`小智平台问学考提示词.md`。
- **求职价值**：现在企业招"AI 应用/ Agent 方向"必看提示词与 Agent 编排能力。

### ② RAG 知识库搭建（Dify 低代码）
- **学到**：知识库上传→自动分段→索引方式（高质量/混合检索 vs 经济模式坑）→TopK→聊天助手编排（检索节点+LLM+回复）。
- **对应文件**：`小智平台问学考知识库说明.md`、`项目梳理_平台分工与进展.md`。
- **求职价值**：RAG 是企业落地 LLM 最普遍的方式，简历可写"基于 Dify 搭建市场监管法规 RAG 问答"。

### ③ 全栈前端（Next.js + TypeScript + React）—— 你正在练的
- **学到**：App Router 页面结构、客户端组件 hooks（useState/useEffect/useRef）、**服务端 API 路由代理**（Key 不暴露前端）、环境变量 `.env.local` 与 gitignore、SVG 动画、浏览器 TTS/ASR API。
- **对应文件**：`dify-frontend/app/page.tsx`、`app/api/chat/route.ts`、`lib/dify.ts`、`大屏演示与启动指南.md`。
- **求职价值**：TypeScript + Next.js 是前端/全栈岗主流栈，能写进简历项目。

### ④ 前后端分离与安全常识
- **学到**：敏感 Key 永远放服务端，前端只调自己的代理接口；`.gitignore` 排除 `.env.local` 防泄密；已踩过"Key 明文写前端"的坑（这里是正确做法，记住 this pattern）。

### ⑤ 语音交互原理（ASR / TTS）
- **学到**：ASR（语音→文本）与 TTS（文本→语音）是什么、浏览器原生实现局限（需外网/权限）、为什么生产要接专业语音模型。

### ⑥ 平台选型与需求拆解思维（比写代码更值钱）

- **对应文件**：`云安区市场监管AI体验方案_内容整理.md` 第五节。

### ⑦ Git 协作（你正在学的）
- **学到**：实际项目中"只读文档/改前端/改提示词"都用 commit 记录；`.env.local` 类配置文件用 VS Code 建（别用记事本，会偷偷加 .txt 后缀导致 git 不识别）。

### ⑧ 项目交付与沟通
- **学到**：把"完成度对照需求表 + 对外话术 + 风险清单"整理成对接文档，是和经理/客户对齐的最高效方式（就是本文件本身）。

**一句话总结你能带走的**：一个"Dify RAG 问答 + Next.js 前端 + 提示词工程 + 语音交互"的完整 AI 应用项目经验，外加"按交互形态做平台选型"的产品思维——这正好是秋招 AI 应用方向最吃得开的履历组合。

## 九、R6 MCP 统一控制 + 部署上线步骤

> 状态：架构文档已明确闭环流程；实际"大屏部署"步骤已成型，"机器人硬件 / MCP 对接"待客户硬件到位后实施。

### 9.1 大屏部署 = 一键启动包（现场 3 步，非技术人员也能做）
> 原 10 步 Runbook 是给开发者写的，现场观感太重。改为**我们本地预构建一次，现场只拷文件夹双击启动**。
>
> ✅ **已实际构建**：`dify-frontend/deploy/` 已生成（standalone server + 自带 node_modules + 启动脚本 `start.cjs/.bat/.sh`），本地冒烟测试页面与视频均返回 HTTP 200。

- **我们本地一次性（开发者做）**：
  1. `next build` + 在 `next.config` 开 `output: 'standalone'`，产出自带运行时的 `.next/standalone` 文件夹；
  2. 写启动脚本 `start.bat` / `start.sh`（内部 `node server.js`，并拉起 Chrome kiosk：`chrome --kiosk --app=http://localhost:3000?scene=welcome`）；
  3. 如需彻底零依赖，可用 `pkg` / `nexe` 把 Node 也打进包。
- **现场人员 3 步（展机操作员做）**：
  1. 把打包文件夹拷到展机；
  2. 双击 `start`；
  3. 完成——浏览器自动全屏打开，无需装 Node / 跑 npm / 手动 F11。
- **前提**：展机系统允许运行该文件夹（普通 Windows 即可）；麦克风权限与联网在首次运行时授权。

**部署后验证**：`curl localhost:3000/api/chat` 返回真实法条；三场景切换正常；TTS 出声；麦克风可识别（联网环境）。

### 9.2 Dify 侧配置（不算"大屏部署"，管 Dify 的人做）
- **换法规库**：客户确认版 4 部法上传 Dify → 高质量 + 混合检索 → **发布**（Dify 网页点几下，不碰大屏电脑）。
- **升模型**：DeepSeek-V4 在 Dify 后台切换。
- 这俩是内容 / 配置动作，与"展机部署"解耦，由负责 Dify 的同学执行。

### 9.3 实体机器人（小智）硬件 / MCP 对接
- **前提**：客户硬件到位，确认小智机器人支持的设备 / 接口。
- **路径 A（小智原生跑，优先）**：若小智能直接承载问/学/考，无需自建 MCP，仅实测真机三模式 + 接入客户语音模型。
- **路径 B（需 MCP 控制硬件）**：搭 MCP Server 连接机器人（移动 / 扬声器 / 麦克风阵列）→ 用户语音 → 小智智能体 →（可选）复用 Dify API 知识库 → 回传机器人展示。
- **实测**：问 / 学 / 考 在真机逐模式验证；**考模式 ABCD 语音识别已实测通过（2026-07-28），判分容错规则保留即可，无需改天干标号**。

### 9.4 MCP 架构说明（来自原方案，留作对接依据）
- **大屏流程**：用户语音 → 麦克风阵列 → ASR → 智能体 → MCP → 对应大屏执行 → 状态反馈闭环。
- **机器人流程**：用户语音/文字 → 小智 → 智能体 → MCP → Dify 知识库引擎 → 路由 教/学/考 → 回传。
- **当前状态**：架构已文档化；实际硬件 / MCP 对接待客户硬件到位后实施。
