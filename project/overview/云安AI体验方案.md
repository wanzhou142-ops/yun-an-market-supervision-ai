## 一、项目目标

依托培训基地的大屏、音响与实体机器人，围绕**市场监管领域知识**构建沉浸式普法体验：
- **数字人交互**：大屏上的数字人引导来访人员参观宣传廊、进入模拟药店。
- **实体机器人交互**：可语音对话的机器人，切换"教/学/考"角色与来访人员互动。
- 核心 AI 能力：AI 视频制作、AI 语音识别、AI RAG 知识问答。

---

## 二、两大体验方案

### 1. 数字人交互方案（大屏 + 音响）
基于大屏/音响实现"法规宣传廊 + 模拟药店场景"，流程分四区：

| 区域   | 内容                                                  | 交互方式              |
| ---- | --------------------------------------------------- | ----------------- |
| 迎宾大厅 | 数字人欢迎来访者（语音合成+小动画）、播放基地总体介绍视频、询问想参观宣传廊还是模拟药店        | 语音合成+小动画+背景切换     |
| 宣传廊  | 数字人介绍宣传廊，询问想进入器械区/化妆品区/药品区；各功能区先介绍，来访人员可**打断并交互咨询** | 语音合成+小动画+视频+生成画面  |
| 模拟药店 | 数字人介绍，可选传统药房区（药品/非药品）、新零售模式区；沟通其中的违法违规现象            | 图片切换+语音识别+智能体比对答案 |
| 控制输入 | 遥控控制（遥控器）+ 语音控制（用麦克风收音，避免人多嘈杂）                      | 麦克风阵列采集           |

### 2. 实体机器人交互方案
制作语音交互机器人，基于市场监管各领域知识库与来访人员对话，可切换三种**角色模式**：

- **教（宣讲老师）**：系统讲解法规、案例与操作流程，标准化知识输出。
- **学（答疑助手）**：实时响应培训提问，调取知识库精准答案并语音反馈。
- **考（评估考官）**：自动出题判分，记录回答得分，形成学习评估闭环。

## 三、AI 技术栈（三大支柱）

| 技术 | 作用 | 对应环节 |
|------|------|----------|
| **AI 视频制作** | 生成执法场景视频与法规宣传素材，降低内容生产成本 | 内容生产 |
| **AI 语音识别（ASR）** | 实时将语音转为文本，支撑自然的人机对话 | 智能交互 |
| **AI RAG 技术** | 基于市场监管知识库精准检索与生成，确保回答有据可依、实时更新 | 知识推理 |

## 四、系统架构（MCP 统一控制流程）

两个方案共用"智能体 + MCP 连接层"的闭环架构：

**① 大屏方案流程**
```
用户语音 → 麦克风阵列采集 → ASR 语音识别(文本)
  → 智能体核心(意图理解/决策)
  → MCP Client → MCP Server → 对应场景大屏
  → 迎宾大厅大屏 / 宣传廊大屏 执行
  → 状态反馈回智能体(闭环监控)
```
MCP = Multi-Device Control Protocol，统一控制协议。

**② 智能机器人方案流程**
```
用户语音/文字 → 小智机器人 → 智能体(意图识别)
  → MCP Client → MCP Server → DIFY 知识库引擎
  → 路由到：教 / 学 / 考 子功能
  → 结果经 MCP + 智能体回传小智机器人 → 展示给用户(闭环)
```
架构目标：模块化、可扩展、可监控、可维护。

## 五、两种落地路径对比

| 维度 | 方案一：基于 Dify 快速实现 | 方案二：服务器深度定制 |
|------|---------------------------|------------------------|
| 工作量 | 1 人/月 | 5 人/月 |
| 实现方式 | 基于小智/Dify 现有流程，对知识库做文档切片 | 服务器部署智���体，需调试硬件对接、搭建服务器 |
| 核心优势 | 快速上线；按场景分类可提高准确率与响应效率 | 可定制功能与输出展示；生成报表/运营数据；可结合 Skill 综合判断、持续优化 |
| 能力边界 | 受 Dify 上限约束；不能显示历史问题，需到 DIFY 后台查看 | 可集合 Skill 能力弥补单一模型不足 |
| 主要风险 | 知识库大小影响工作量，条目可能需人工整理；知识量过大时自动切片有断点、难达 100% 准确 | 需摸清硬件能力，开发调试周期长 |
| 适用建议 | 轻量快速 | 深度定制、长期运营 |

**补充说明（docx）：**
- 方案一：100 万字以内 Deepseek 可支持，超 100 万需切片；准确率取决于知识库大小。
- 方案二：可生成运营数据报表（哪些问题被问得最多）、做智能分析、训练 AI 能力，准确率更高；需获取硬件、成本更高。

## 六、结论与建议

- 两方案并非互斥：大屏数字人 + 实体机器人可并行建设。
- 选型原则：**轻量快速选 Dify，深度定制选服务器部署**。
- 建议根据项目**紧急程度**与**长期运营需求**综合评估后再定路径。
