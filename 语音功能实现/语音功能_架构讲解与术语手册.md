## 〇、项目语音链路总览

你们项目的语音走的是**离线**路线（客户机不联网也能跑）。整条链路：

```
[用户说话]
   │ 麦克风采集（Web Audio API，请求 16kHz 单声道 PCM，浏览器可能回退 48k → 服务端 _resample_pcm 兜底）
   ▼
[前端 dify-frontend]
   ├─ VAD 语音活动检测（自适应能量法，见第三节）
   ├─ encodeWAV（把 PCM 合法化到 [-1,1] 再打包成 WAV）
   └─ POST /api/voice/asr  ──┐
                             │
[语音服务 voice-service :8000]│
   ├─ /asr  → Vosk 模型识别（声音→文字）
   └─ /tts  → Piper 合成（文字→声音）  ← 仅合成"预录未覆盖"的兜底话术
                             │
[前端 classify] 纯前端规则判意图（返回 / 点名场景 / 子分区 / 闲聊）
   │ 不调 Dify（RAG 已移交小智，前端只做规则导航）
   ▼
[状态机 + scriptFor] 按意图 setNav 切视频 + 取固定话术文本
   │
   ▼
[前端 speak] 优先播预录 mp3（tts-map.json），缺失回退 Piper 实时合成
```

要点：
- 前端只调本机 `127.0.0.1:8000`，**前端代码不感知离线/在线**（所以将来要切在线 API，只需改 `server.py` 内部）。
- VAD 是整条链路的**第一道闸门**：只有判定「有人说话」才提交 ASR，否则丢弃静音帧，省算力也避免误识别。
- **整条链路不调 Dify / 任何 LLM**：回答话术由前端 `scriptFor` 按场景+性别从固定模板拼接，能用预录 mp3 就播预录。知识类问答（RAG）已移交小智平台，本大屏只做导航引导。
- **35 秒无操作自动回视频模式**：`IDLE_TIMEOUT_MS` 读 `NEXT_PUBLIC_IDLE_TIMEOUT_MS`，默认 35000。

## 一、核心术语（先认脸）

| 术语 | 英文 | 一句话 | 在你们项目的位置 |
|---|---|---|---|
| 语音识别 | ASR | 声音→文字 | `voice-service/server.py` 的 `/asr` 路由，内部用 Vosk |
| 语音合成 | TTS | 文字→声音 | `/tts` 路由，内部用 Piper；预录 mp3 在前端 `public/` |
| 语音活动检测 | VAD | 判断「此刻有没有人说话」 | `lib/voice.ts` 的 VAD 状态机（自适应能量法） |
| 回声消除 | AEC | 把喇叭播出的声音从麦克风里抠掉 | **本项目刻意关掉**（见第五节） |
| 双讲检测 | DTD | 判断「双方同时说话」避免 AEC 误杀 | 在线全双工方案才需要 |
| 实时传输 | WebSocket | 边采边传、边收边播的双向通道 | 专业实时方案用，本项目用 REST |
| 脉冲编码调制 | PCM | 原始音频采样数据（Float32 数组） | 麦克风 onaudioprocess 回调里的 `ch` |
| 波形音频 | WAV | 给 PCM 加文件头的容器格式 | `encodeWAV()` 生成，发给服务端 |
| 采样率 | sampleRate | 每秒采多少点（你们请求 16kHz） | 浏览器请求 16k，服务端 `_resample_pcm` 兜底 |
| 均方根能量 | RMS | 一帧音频的平均响度 | VAD 判定「说话/静音」的唯一依据 |
| 满幅分贝 | dBFS | 相对最大振幅的分贝值 | RMS 取对数即 dBFS，调试用 |

## 二、架构分层（自上而下四层）

1. **采集层（前端）**：Web Audio `getUserMedia` 拿麦克风流，`ScriptProcessorNode`（你们当前）逐帧拿到 PCM。
2. **检测/编码层（前端）**：VAD 判断说话边界 → `encodeWAV` 打包 → 触发提交。
3. **服务层（voice-service）**：REST `/asr`、`/tts`。ASR 用 Vosk small（43MB 离线模型），TTS 用 Piper（60MB 离线模型）。
4. **应用层（前端）**：`classify` 纯前端规则把文字转意图 → 状态机 `setNav` 切视频 + `scriptFor` 取固定话术 → `speak` 播预录/合成。**不调 Dify**（RAG 移交小智，前端只做规则导航与话术拼接）。

> 调试抓手：链路任何一环出问题，先看 `voice.ts` 里的 4 条 `onDebug` 日志（grace / 检测到人声 / 静音说完 / 提交超时），详见 `语音功能复盘与客户机部署指南.md` §7 F4。

## 三、自适应能量 VAD（你们项目的实现）

### 3.1 为什么用「自适应」而不是固定阈值
最早你们用**固定阈值 0.012**：安静房间的本底噪声正好卡在阈值附近，VAD 分不清「说话」和「安静」，一直录到最长时长才提交，体验像「说完要等满 10 秒」。后降到 0.008 让轻声用户也能触发。

改成**自适应**：先花 `START_GRACE_MS`（约 400ms）测环境底噪 `noiseFloor`，再按相对底噪判定；阈值同时外置成环境变量，现场可调：
```js
// lib/voice.ts 核心逻辑（当前代码）
const ABS_FLOOR   = Number(process.env.NEXT_PUBLIC_VAD_FLOOR) || 0.008;  // 绝对下限（默认0.008，原0.012偏严）
const VAD_START_K = Number(process.env.NEXT_PUBLIC_VAD_START_K) || 2.2;  // 起音倍率
const VAD_END_K   = Number(process.env.NEXT_PUBLIC_VAD_END_K) || 1.6;   // 止音倍率
const startTh = Math.max(noiseFloor * VAD_START_K, ABS_FLOOR);  // 起音阈值
const endTh   = Math.max(noiseFloor * VAD_END_K, ABS_FLOOR);   // 止音阈值
```
- `noiseFloor` 是安静环境的 RMS；说话时 RMS 通常 ≥ 底噪 ×2.2，于是判定「起音」。
- 安静展厅和嘈杂展厅都能自动适配——这就是「自适应」的价值。
- **现场可调**：中青年/正常音量 → 0.008；老年/轻声/儿童 → 0.008（已够）；嘈杂展馆 → 0.015~0.020。改 `.env.local` 不需动代码。

### 3.2 状态机
```
[grace 测底噪] → [检测中：RMS>startTh? → 标记 speechStarted]
               → [说话中：RMS<endTh 持续 350ms? → 标记说完]
               → [最长 8s 强制提交]
```

### 3.3 两个真实踩过的坑（已修）
- **Bug A**：`if (noiseFloor === 0)` 用严格相等当哨兵，但 grace 全静默时 noiseFloor 被设回 0 → 每帧重触底噪日志、自适应失效。**修复**：改用独立标志 `vadInitDone`（只初始化一次）。
- **Bug C**：`ScriptProcessorNode` 偶发返回超 [-1,1] 的污染值（RMS 显示 3.99）。**修复**：`encodeWAV` 已有 `Math.max(-1, Math.min(1, x))` clamp，提交给 Vosk 的永远合法。详见复盘指南 §3。

## 四、VAD 方法对比（不止能量法）

| 方法 | 原理 | 你们用的？ | 适用 |
|---|---|---|---|
| 能量法 | 每帧 RMS 超阈值=说话 | ✅ 是（自适应） | 安静/中等环境，零依赖 |
| 过零率 ZCR | 数波形过零点，区分清/浊音/噪声 | 常和能量法搭配 | 辅助判定 |
| 频谱特征 | MFCC / 谱平坦度 / 谱质心 | ❌ | 能区分音乐/噪声/人声 |
| 统计模型 GMM/HMM | 算「这帧更像语音还是噪声」 | ❌（WebRTC VAD 内部用） | 比裸能量稳 |
| **WebRTC VAD** | GMM 实现，几 KB，行业事实标准 | 可升级项 | 轻量专业首选 |
| **Silero VAD** | 小神经网络 ONNX，几 MB | 可升级项 | 当前 AI 语音主流，准度最高 |

> 结论：能量法 = 入门「能用」级；想更稳 → WebRTC VAD（最小代价）；想专业 AI 体验 → Silero VAD。

## 五、AEC 与 VAD 的关系（你们为什么关掉 AEC）

- **AEC（回声消除）**干的事：数字人自己播报的声音会从喇叭漏进麦克风，AEC 把它从麦克风信号里减掉，否则「自己听到自己」会自激。
- **你们的选择**：刻意**关掉 AEC**（`voice.ts` 里 `echoCancellation: false`），原因是保留原始波形给 Vosk 保真（AEC 处理会改波形，可能伤小模型识别）；改用**半双工锁**规避回声——AI 播报时（`speaking=true`）前端的 `startListening()` 直接 `return` 不开麦，等播完再听。
- **唤醒机制**：**唤醒=屏幕按钮**（点「开始互动」触发，视频模式一直播、无人不中断），**不靠说"安安"唤醒**。语音里的「安安」现在只作**闲聊词**（如"安安你好"），不再拦截导航——这样"安安带我去宣传廊"也能正常导航。
- **代价**：不能做真正的「边听边说」全双工。但展厅是「按钮触发 + 轮流对话」，半双工足够，且更简单稳。
- **何时该开 AEC**：如果将来切在线 API、做全双工（像小智实体机器人那样），就必须上 AEC（WebRTC AEC3 / SpeexDSP）。详见 `回声消除AEC_技术知识库.md`。

> 推论：因为你们关了 AEC、靠半双工，所以 **VAD 比在普通全双工系统里更关键**——它必须在「用户真正说话」那一刻才开麦，错判就会吞掉用户首句或误触发。

## 六、离线 vs 在线语音 API

| 维度 | 离线（你们当前） | 在线 API |
|---|---|---|
| 识别准确率 | 一般（Vosk small） | 高（云端大模型） |
| TTS 自然度 | 偏生硬（Piper） | 很自然（精品音色） |
| 模型体积 | 要下 ~115MB 离线包 | 免下载 |
| 联网 | 不需要 | 必须 |
| 隐私 | 音频不出本机 | 音频上传云端（政务需注意） |
| 费用 | 免费 | 按量付费 |

选离线的硬约束：**客户机展厅不联网**。在线 API 的接法见 `语音功能复盘与客户机部署指南.md` 的后续迭代项。

## 七、开源对标（行业怎么做）

专业实时语音项目（GitHub 上常见的「AI 语音助手 / 数字人」骨架）通常：
- 用 **WebSocket 流式**而不是 REST，把延迟压到 <1.5s；
- VAD 用 **Silero VAD** + AEC 用 **WebRTC AEC3**；
- TTS 用**流式合成**（边生成边播，不等地整段）。
你们当前是「REST + 能量 VAD + 半双工」，属于**交付优先的稳妥版**，后续可按上面路径升级。

## 八、术语速查表（背这 8 个就够入门）

- **ASR**：语音转文字（你们=Vosk）
- **TTS**：文字转语音（你们=Piper + 预录 mp3）
- **VAD**：判断是否有人在说话（你们=自适应能量法，阈值外置可现场调）
- **AEC**：回声消除（你们=关掉，靠半双工锁 + 屏幕按钮唤醒）
- **PCM**：原始采样点数组（麦克风直接给的）
- **WAV**：PCM 加文件头（发给服务端的格式）
- **RMS**：一帧平均响度，VAD 的判定依据
- **WebSocket**：双向流式通道（升级在线方案时用）
