# 01 · 场景切换交叉淡化 + 运镜

> 对应需求：背景和数字人切换时间不一致、太僵硬 → 改为重叠交叉淡化 + 背景推近 + 人物落位，时长 420ms 同步。

## 一、实现流程

**核心思路**：场景切换时，**不卸载旧场景、也不瞬切**，而是让"旧场景"和"新场景"两层**同时存在于屏幕上短暂重叠**——旧层在上淡出、新层在下淡入，重叠期间画面始终有内容，因此无空白帧、无硬切。

### 1. 状态机（`page.tsx`）

```
curScene : 当前已落定的场景（新层）
prevScene: 正在淡出的旧场景（过渡结束后清空）
SCENE_FADE_MS = 420   // 背景与数字人共用，保证二者同步
```

切换监听（`page.tsx:501-507`）：
```ts
useEffect(() => {
  if (nav.scene === curScene) return;
  setPrevScene(curScene);          // 旧场景留驻上层淡出
  setCurScene(nav.scene);          // 新场景落到下层并淡入
  const t = setTimeout(() => setPrevScene(null), SCENE_FADE_MS); // 420ms 后卸载旧层
}, [nav.scene, curScene]);
```

### 2. 背景双图层（`page.tsx:756-770`）

```tsx
<img key={curScene}  className="bg-photo bg-cross-in"  src={...curScene.photo} />
{prevScene && <img key={prevScene} className="bg-photo bg-cross-out" src={...prevScene.photo} />}
```
- 关键是 `key={curScene}` / `key={prevScene}`：**React 用 key 区分元素**，换 key 会强制重新挂载 DOM 节点 → CSS 动画重新从头播放（否则同一节点改 class 不会重放 `@keyframes`）。
- `bg-cross-in`（下层）播放 `bgCrossIn`(opacity 0→1) + `kenBurns`(scale 1.14→1.08 推近)
- `bg-cross-out`（上层）播放 `bgCrossOut`(opacity 1→0)

### 3. 数字人双图层（`page.tsx:851-859` + `globals.css`）

```tsx
<Avatar key={curScene}  cross="in"  ... />
{prevScene && <Avatar key={prevScene} cross="out" ... />}
```
- `.avatar-cross-in` = `avatarCrossIn`(淡入) + `avatarSettle`(从上沉微缩 `translateY(8px) scale(.98)` → 归位，模拟"落位")
- `.avatar-cross-out` = `avatarCrossOut`(淡出)

### 4. 时长注入

`--scene-fade` 通过 `style` 内联传入（`page.tsx:715`、`853`），CSS 里用 `var(--scene-fade, 420ms)` 读取。这样**改时长只动一处常量** `SCENE_FADE_MS`，CSS 自动跟随。

## 二、技术栈

| 技术 | 用途 |
|------|------|
| React `useState` + `useEffect` | 双图层状态机、420ms 定时器 |
| CSS `@keyframes` + `animation: ... forwards` | 交叉淡化、运镜、落位（`forwards` 让动画停在终态） |
| `object-fit: cover` / `contain` | 背景铺满 / 数字人按比例 |
| React `key` 重挂载 | 强制重放动画（常被忽略的关键技巧） |
| `will-change: opacity, transform` | 提示浏览器提前提升为独立合成层 |
| `transform: scale` 做 kenBurns | 用 GPU 合成而非重排，省 CPU |

## 三、踩的坑

1. **单图层顺序溶解 → 空白帧**
   最早是"旧层淡出完再淡入新层"，中间有 1 帧全透明 → 肉眼可见闪一下。改**双图层重叠**后消失。

2. **切换偶发卡顿（不是动画逻辑问题，是资产太大）**
   背景原图 4032×3024、人物 1344×3168，单个 PNG 十几 MB，切换时解码压垮 GPU。解决见 [06-资产优化与切换性能](06-资产优化与切换性能.md)。

3. **过渡期双层同时算 drop-shadow 掉帧**
   透明 PNG 的 `drop-shadow` 是按 alpha 逐像素算轮廓阴影，两层同时算 → 切换掉帧主因之一。临时方案（`.avatar-cross-in .avatar-img, .avatar-cross-out .avatar-img { filter: none }`）：过渡期间关掉阴影，420ms 肉眼不可察，层卸载后自动恢复（`globals.css:153-156`）。

4. **`key` 没换导致动画不重放**
   若两层用同一个 `key`，React 认为是同一节点只更新 class，CSS 动画不会从头播。必须 `key={scene}` 让新旧场景是不同节点。

## 四、学习建议（可深挖的概念）

- **CSS 动画 vs JS 动画**：本项目全用 CSS `@keyframes` 跑过渡，因为浏览器能把 CSS 动画交给合成器线程（GPU），不阻塞主线程 JS；用 `requestAnimationFrame` 手写也会更可控但更易掉帧。
- **合成层（Compositing Layer）**：`will-change` / `transform` / `opacity` 动画会触发元素提升为独立层。为什么只用这两个属性做动画？因为它们**不触发重排（reflow）和重绘（repaint）**，只走合成，性能最好。改 `width/left/top` 就会触发重排，卡。
- **React 受控动画的坑**：CSS 动画是"一次性"的，重放必须让节点重新挂载（换 `key`）或移除再添加 class。这是前端动画常见陷阱。
- 延伸阅读：`will-change` 的滥用风险（不要给太多元素常开）、`animation-fill-mode: forwards` 的作用。
