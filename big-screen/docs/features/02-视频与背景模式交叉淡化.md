# 02 · 视频 ↔ 背景模式交叉淡化

> 对应需求：从"待机视频"进入"数字人交互"、以及返回，也要用和场景切换一样顺滑的交叉淡化，不要硬切。

## 一、实现流程

大屏有两种**模式**：

```
video        = 仅播放宣传视频（右下角一个"开始互动"按钮）
interactive  = 数字人出现、可语音对话
```

之前 `bg-layer` 按 `mode` 硬切：视频模式渲染 `<video>`，交互模式渲染照片双图层。点"开始互动"/"返回视频"时视频直接卸载、照片瞬现 → 硬切闪烁。

### 1. 视频层常驻挂载（`page.tsx:726-747`）

```tsx
<video
  key={videoSrc}
  className={
    "bg-video" +
    (mode === "interactive" && !modeOut ? " is-hidden" : "") +  // settled 后隐藏
    (modeOut === "interactive" ? " bg-fade-in"  : "") +          // 返回视频时淡入
    (modeOut === "video"       ? " bg-fade-out" : "")             // 进入互动时淡出
  }
  ...
/>
```

- **视频不再随 mode 卸载**，始终在 DOM 里。靠 class 控制透明度，才能做交叉淡化。
- `is-hidden`（`globals.css:135` `opacity:0`）：交互 settled 后视频完全隐藏，但**不卸载**——保证"返回视频"瞬时恢复，不用重新加载/解码视频。

### 2. 过渡状态 `modeOut`（`page.tsx:416-428`）

```ts
const [modeOut, setModeOut] = useState<"video" | "interactive" | null>(null);
useEffect(() => {
  const old = modeRef.current;
  if (old !== mode) {
    setModeOut(old);                                  // 旧模式留驻参与淡出
    const t = setTimeout(() => setModeOut(null), SCENE_FADE_MS);
    modeRef.current = mode;
    return () => clearTimeout(t);
  }
}, [mode]);
```

`modeOut` 记录"正在淡出的那个旧模式"，420ms 后清空。用途：决定视频当前该 `bg-fade-in`（从交互回到视频）还是 `bg-fade-out`（从视频进入交互）。

### 3. 照片组整组淡入淡出（`page.tsx:750-771`）

```tsx
{(mode === "interactive" || modeOut === "interactive") && (
  <div className={"bg-photos-layer" + (modeOut === "interactive" ? " bg-fade-out" : "")}>
    {/* 场景照片双图层（见 01 篇） */}
  </div>
)}
```

- `.bg-photos-layer`（`globals.css:113` `z-index:1`）压在视频层（`z-index:0`）之上。
- **进入互动**：视频层 `bg-fade-out` 在下淡出、照片层在上淡入 → 照片覆盖视频。
- **返回视频**：照片层 `bg-fade-out` 在上淡出、视频层 `bg-fade-in` 在下淡入 → 视频覆盖照片。

### 4. 防坑：原声解锁时机

```tsx
onCanPlay={(e) => {
  const v = e.currentTarget;
  if (mode === "video") { v.muted = false; v.play(); } // 仅视频模式解锁原声
}}
```
交互模式里视频被遮挡且静音（作背景、避免和 TTS 朗读冲突），**不在此解锁声音**，否则背景视频一播放就盖过数字人讲解。

## 二、技术栈

| 技术 | 用途 |
|------|------|
| React 状态 `mode` + `modeOut` | 模式切换的双层过渡编排 |
| CSS `opacity` 交叉淡化 | 视频 ↔ 照片整组过渡 |
| `z-index` 层叠 | 照片组(1) 盖在视频(0) 之上 |
| `is-hidden` + 保留实例 | 隐藏但不卸载，瞬时恢复 |

## 三、踩的坑

1. **硬切闪烁**：最早 `mode === "video" ? <video/> : <照片/>` 三元渲染，切换时一个卸载一个挂载，中间有空白帧。必须让两层**在过渡期同时存在**，靠 opacity 而非挂载/卸载来切换。

2. **视频卸载后恢复慢**：若交互模式真卸载 `<video>`，返回视频时要重新请求+解码，大屏上会有明显卡顿。用 `is-hidden`（只 `opacity:0`）保留实例解决。

3. **背景视频和 TTS 抢声**：交互模式下若视频原声未静音，会和数字人朗读重叠。靠 `mode==="interactive"` 时 `v.muted=true` 强制静音（命令式控制绕过 React 对 `muted` 属性的更新 bug，见 `page.tsx:512-517`）。

## 四、学习建议

- **"隐藏 vs 卸载"的性能权衡**：大屏/游戏里常把"暂时看不见但很快要用"的元素隐藏而非销毁（保留实例），避免重复解码/重建的开销。这是前端性能的常见套路。
- **`muted` 的 React 坑**：React 对 `<video muted>` 有已知更新 bug（某些版本不更新），所以本项目用 `useEffect` 命令式 `v.muted = ...` 直接改 DOM 属性，绕过它。
- 延伸：视频自动播放策略（浏览器要求 `muted` 才能自动播放，`playsInline` 防 iOS 全屏）。
