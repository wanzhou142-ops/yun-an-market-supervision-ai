# 04 · 数字人形象体系（去背 / 对齐 / 放大 / 光圈）

> 对应需求：三场景数字人大小一致、脚底/头顶与身后光圈在同一水平线；数字人和光圈放大 30%；讲解动画适当下移。

## 一、实现流程

数字人 = **透明 PNG 立绘**（AI 生成 → 去背 → 规范化 → 放大），叠在模糊背景照片之上，背后一个旋转光环 + 辉光。

### 1. 去背（生产侧，非前端）

- 源图在 `assets-original/avatar-*.png`（已去背、无压缩，质量最高）。
- 去背用 `rembg`（isnet-general-use 模型）+ onnxruntime，策划期用过；交付用 `assets-original` 里的成品，前端不再去背。
- 药店数字人曾因"半身像太靠前"重画：用图生图只改睁眼、保留画风，再去背落地 `public/avatar-pharmacy.png`。

### 2. 规范化对齐（治本，[`scripts/tools/normalize_avatars.py`](../../scripts/tools/normalize_avatars.py)）

**根因**：三张源图虽都是 1200 高画布，但"人物实际占比 + 垂直位置"不一致 → `object-fit: contain` 后大小/水平线不齐。宣传廊源图分辨率还是另两张的 ~3 倍（1344×3168），视觉最大。

**做法**：脚本用 PIL 读每张 PNG 的 **alpha 通道**，算出人物真实包围盒，把人物统一重排到 **650×1300** 画布：
- 人物统一显示高 `1220`
- 脚底基线 `y≈1260`、头顶 `y≈40`、**水平居中**

重写后三图全部 `650×1300`、人物高 `1218`、脚底 `y≈1258`、均居中 → `contain` 进同一容器后完全对齐。

落地步骤（遵守数据安全铁律）：
```
1) 备份 public/avatar-*.png → public/_backup/
2) 用 scripts/tools/_tmp_normalized/normalized_*.png 覆盖 public/
```

### 3. 放大 30%（`globals.css:516-521`）

```css
.avatar-stack {
  width:  min(68.9vh, 754px);   /* 原 53vh / 580px */
  height: min(80.6vh, 884px);   /* 原 62vh / 680px */
}
```
- 因 `.halo-svg` 用 `124%`、`.avatar-glow` 用 `inset:-10%`，都**按容器比例缩放** → 光圈/辉光自动同步放大约 30%，无需单独写样式。
- 响应式（矮屏 `@media max-height:760px`）同步放大到 `49.4vh×59.8vh`。

### 4. 讲解动画下移（`globals.css:560-574`）

```css
@keyframes speakPulse  { 100% { transform: scale(1.04) translateY(6px);  } } /* 原 -4px */
@keyframes speakFloat  { 100% { transform: translateY(8px);             } } /* 原 -10px */
```
- `.avatar-img` 的 `transform-origin: center bottom` 让 `scale(1.04)` 从脚底往上长。放大 30% 后顶端更贴顶栏，原向上 `translateY` 会撞顶 → 改为**向下**飘，避开顶部，也不撞底部状态框（`translateY` 作用在 img 上，不影响 flex 布局里的 status 位置）。

### 5. 形象结构（`page.tsx:956-989` `Avatar` 组件）

```
.avatar-wrap
 ├─ .avatar-glow     背后辉光（radial-gradient，呼吸）
 ├─ .halo-svg        旋转光环（SVG circle，stroke-dasharray 虚线，spin）
 └─ .avatar-img      数字人 PNG（object-fit: contain）
```

## 二、技术栈

| 技术 | 用途 |
|------|------|
| PIL（Python）alpha 包围盒分析 | 量化人物占比/位置，驱动规范化 |
| `object-fit: contain` | 画布等比缩放进容器 |
| CSS `transform-origin` / `scale` | 放大落点控制 |
| SVG `<circle>` + `stroke-dasharray` + `spin` | 旋转虚线光环 |
| `radial-gradient` + `breathe` | 背后辉光呼吸 |

## 三、踩的坑

1. **"画布等高"≠"人物等大"**：三图都是 1200 高，`contain` 顶满容器高，但人物在画布里的占比不同（80.6% / 89.6% / 83.4%）→ 视觉大小不同。必须看**人物真实像素**而非画布。

2. **宣传廊源图分辨率异常高（1344×3168）**：叠加"占比最高"双重因素 → 最大。规范化时统一重排到 650×1300 才解决，也顺带把体积从十几 MB 降到 ~600KB。

3. **半身像"贴脸"**：药店最早是半身像，头身比 0.355 偏离全身 0.298/0.318 → 视觉太靠前。改图生图睁眼全身版（0.324）才和前两场景取景对齐。

4. **放大后撞顶**：只放大不加动画修正，数字人头顶会贴住/超出顶栏。靠把讲解 `translateY` 改向下 + `transform-origin: center bottom` 从脚底生长解决。

## 四、学习建议

- **"画布 vs 内容"的区分**：PNG 有透明留白，视觉元素只占其中一部分。做素材对齐时，永远按"alpha 通道里的真实内容"算，不要按"整张画布"算。这是设计/前端协作常踩的坑。
- **`object-fit: contain` 的语义**：它按"整张图（含透明）"缩放，所以上游图片规范统一，下游布局才稳。这也是为什么本项目要"出图规范"（650×1300、人物高~1220、脚底 y≈1260、居中）——**规范前置，比前端硬凑省事**。
- **可复用脚本化**：`normalize_avatars.py` 把"对齐"变成一条命令，未来加场景直接跑脚本，不用手工调。这种"把设计规范变成代码"的思路值得内化。
- 延伸：PNG alpha 通道、SVG `stroke-dasharray`、CSS `transform-origin` 对 scale/rotate 的影响。
