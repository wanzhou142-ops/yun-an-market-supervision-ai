# 08 · 唤醒与空闲超时

> 对应需求：大屏**不用语音唤醒词**，靠屏幕按钮触发；无人交互 35 秒后自动回到视频模式。

## 一、实现流程

### 1. 唤醒 = 屏幕按钮（非语音唤醒词）

设计决定：展厅嘈杂，语音唤醒词误触发率高，故**唤醒靠点击"开始互动"按钮**，不靠"嗨安安"之类的唤醒词。

```tsx
// page.tsx:790-793 视频模式下的唯一入口
<button className="enter-btn" onClick={enterInteractive}>
  <span className="enter-ico">🎤</span><span>开始互动</span>
</button>

// page.tsx:554-566 enterInteractive
function enterInteractive() {
  setMode("interactive");
  bgVideoRef.current.muted = true;        // 进入互动：背景视频静音
  awaitingFirstRef.current = true;        // 等访客第一句回复判性别
  const say = welcomeLine();              // "您好，我是安安…"
  setLastAi(say); setMessages([...]); setAiFresh(true);
  speak(say);                             // 数字人先问好
}
```

- 进入交互后数字人**先问好**，等访客开口，再据该句音高判性别、问参观意向（见 `handleUser` 的 `awaitingFirstRef` 首问分支，`page.tsx:589-621`）。
- 返回视频：`exitToVideo()`（`page.tsx:569-579`）收起数字人、恢复背景视频原声。

### 2. 空闲超时自动回视频（`page.tsx:521-529`）

```ts
useEffect(() => {
  if (mode !== "interactive") return;
  if (speaking || listening) return;     // 活动进行中不计时
  const timer = setTimeout(() => {
    pushDebug("空闲 35s，自动返回视频模式");
    exitToVideo();
  }, IDLE_TIMEOUT_MS);
  return () => clearTimeout(timer);
}, [mode, speaking, listening]);
```

- `IDLE_TIMEOUT_MS = Number(process.env.NEXT_PUBLIC_IDLE_TIMEOUT_MS) || 35000`（`page.tsx:17`）——**时长可配**，默认 35 秒。
- 计时依赖 `[mode, speaking, listening]`：数字人讲解中（`speaking`）或聆听中（`listening`）不计时；一旦活动结束且 35s 无操作，自动回视频。

### 3. 刷新永远从迎宾开始（`page.tsx:453-462`）

```ts
useEffect(() => {
  setNav({ scene: "welcome", aspect: null, zone: null });  // 强制回迎宾
  if (window.location.search.includes("scene="))
    router.replace(window.location.pathname, { scroll: false }); // 清掉 URL 上的 scene 参数
}, []);
```
避免用户点 tab 切到别的场景后刷新，跳到非迎宾场景（不符合演示要求）。

## 二、技术栈

| 技术 | 用途 |
|------|------|
| React `useState(mode)` | 视频 / 交互 两模式 |
| `useEffect` + `setTimeout` + 依赖数组 | 空闲计时，活动状态变化即重置 |
| `process.env.NEXT_PUBLIC_*` | 超时时长可配（无需改代码） |
| `router.replace` | 清 URL 参数、刷新回迎宾 |

## 三、踩的坑

1. **计时依赖要包含 speaking/listening**：若只在 `mode` 变化时才设计时器，数字人讲解 10 秒期间计时器不重置，讲解完可能立刻触发"空闲超时"。把 `speaking, listening` 放进依赖数组，活动一结束才重新计时，才符合"无操作 35s"语义。

2. **唤醒方式选型**：曾考虑语音唤醒词，但展厅嘈杂 + Vosk 小模型误触发率高，改为屏幕按钮唤醒。这是"技术可行性 vs 体验"的取舍，值得记住——**不是所有场景都适合语音唤醒**。

3. **刷新残留状态**：URL 上 `?scene=xxx` 残留会让刷新跳错场景。强制 `setNav(welcome)` + 清 URL 参数双保险。

## 四、学习建议

- **`useEffect` + `setTimeout` 做"防抖/超时"**：依赖数组决定"什么变化会重置计时器"。本项目用 `[mode, speaking, listening]` 实现"活动中不计时"。这是前端做 idle/超时/防抖的通用范式，和 debounce 同源。
- **可配置优于硬编码**：超时时长用 `NEXT_PUBLIC_IDLE_TIMEOUT_MS` 注入，现场调试不用改代码重编译。`NEXT_PUBLIC_` 前缀是 Next.js 把变量打进客户端的约定。
- **唤醒策略的取舍**：语音唤醒 vs 按钮唤醒 vs 红外/雷达感应，取决于环境噪声、误触发成本、隐私。公共大屏常因噪声放弃纯语音唤醒。
- 延伸：React `useEffect` 清理函数（return clearTimeout）、Next.js 环境变量（`NEXT_PUBLIC_` 与 server-only 区别）、防抖(debounce)与节流(throttle)。
