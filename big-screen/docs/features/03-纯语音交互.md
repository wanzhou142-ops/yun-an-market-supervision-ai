# 03 · 纯语音交互（删除文字输入）

> 对应需求：只保留语音控制（麦克风），删除文字输入框+发送按钮；数字人变大；底部提示文案按场景/子分区不同。

## 一、实现流程

### 1. 删除文字输入

`page.tsx` 移除了原来的底部输入栏（`<footer className="bottom-bar">`：input + 发送 + 旧 hint）。连带删除：
- `const [input, setInput]` 状态
- 4 处 `setInput("")`（switchScene、叫名字×2、handleUser）

**严格保住语音链路**：只动 UI 层，麦克风按钮 `startListening()` → `voiceRef.current.listen()` → ASR → `handleUser()` 这条链路**一行未改**，确保"删文字输入但不破坏语音功能"。

### 2. 麦克风悬浮按钮（`page.tsx:919-926` + `globals.css:710`）

```tsx
<button className={"mic-fab" + (listening ? " listening" : "")} onClick={startListening}>
  <span className="mic-ico">🎤</span>
</button>
```

- `position: fixed; right:40px; bottom:40px; z-index:14; 104px 圆钮`
- 待机：`micBreathe` 呼吸光晕（提示"可以点我说话"）
- 录音中：`.listening` 转红 + `pulse` 心跳，状态一眼可辨
- 直径 104px 远超大屏可靠命中下限（~80px），适合展厅远距离点触

### 3. 底部提示条（随场景变化）（`page.tsx:181-200` + `hintFor`）

`hintFor(nav)` 按「场景 + 子分区」返回不同引导文案，例如：

| 状态 | 提示 |
|------|------|
| 迎宾 | 可以说「去宣传廊」「去模拟药店」 |
| 宣传廊·器械区 | 可以说「化妆品」「药品」换专区，或「模拟药店」去体验区，或「返回」回宣传廊 |
| 模拟药店 | 可以说「传统药房区」「新零售模式区」，或「去宣传廊」 |

仅作**文案引导**，不参与意图识别（识别在 `classify` 里，详见 [05-子分区导航](05-子分区导航.md) 与 [07-语音链路](07-语音链路.md)）。

### 4. 数字人放大（见 [04-数字人形象体系](04-数字人形象体系.md)）

容器从 `53vh×62vh` 放大到 `68.9vh×80.6vh`（约 +30%），光圈/辉光按比例自动同步放大。

## 二、技术栈

| 技术 | 用途 |
|------|------|
| React 条件渲染 `mode === "video" ? ... : ...` | 视频模式 vs 交互模式两套 UI |
| `position: fixed` 悬浮控件 | 麦克风/提示条不占文档流，空间让给数字人 |
| CSS `@keyframes` 呼吸/心跳 | 麦克风待机/录音状态可视化 |
| 函数式文案 `hintFor(nav)` | 按状态返回不同提示（纯前端，无后端） |

## 三、踩的坑

1. **删功能时误伤语音**：本项目最强调的约束是"删文字输入但绝不破坏语音"。做法是**只删 UI 与 state，不动 `startListening/handleUser/classify` 链路**，改完用 tsc 校验 + 真机验证语音仍能跳场景。

2. **麦克风放右下角会和子分区按钮打架**：子分区入口原在左下，后移到右侧竖排（`zone-chips`，见 05 篇），正是为了错开右下角的麦克风，也避开顶部标题栏。

3. **提示文案和实际可识别词要一致**：`hintFor` 列出的词（如"模拟药店"）必须在 `SCENE_JUMP` / `ZONE_KEYWORDS` 里有对应项，否则用户照着说却没反应。两者是"同一份导航能力"的两面。

## 四、学习建议

- **"删功能"的工程纪律**：当需求是"去掉 A 但保住 B"，第一反应是划清 A、B 的边界——本项目 A=文字输入 UI，B=语音 ASR→意图→TTS 链路，二者解耦得干净，删 A 才不会影响 B。写代码时把"输入源"抽象成统一入口（`handleUser(text)`）是个好设计：文字和语音都只是它的上游，换输入方式不动核心逻辑。
- **大屏交互的触控尺寸**：公共大屏是远距离点触，控件要够大（>80px），这和手机/桌面设计不同。
- 延伸：`position: fixed` 与文档流的关系、z-index 堆叠上下文。
