# 07 · 语音链路（Vosk + Piper + VAD + 性别 + 预录）

> 这是项目的"听"和"说"引擎：麦克风 → 录音 → ASR 识别文字 → 意图分流（前端）→ TTS 合成语音 → 播放。全程**离线**（客户机不连外网）。

## 一、实现流程（端到端）

```
[浏览器] 麦克风录音(16k mono WAV)
   │  POST /api/voice  (二进制音频)
   ▼
[Next.js 代理] app/api/voice/route.ts  → 转发到本机语音服务
   │  POST http://127.0.0.1:8000/asr
   ▼
[voice-service] server.py  → Vosk 模型识别 → {text, gender}
   │
   ▼ (返回前端)
[浏览器] classify(text) 意图识别 → handleUser → 决定导航/话术
   │  POST /api/voice/tts  {text}
   ▼
[voice-service] /tts → Piper 合成 wav/mp3 → 返回音频二进制
   │
   ▼
[浏览器] <audio> 播放（命中预录则直接播本地 mp3）
```

## 二、前端语音抽象层（`lib/voice.ts`）

`createVoiceProvider()` 返回两种实现，由 `NEXT_PUBLIC_VOICE_PROVIDER` 切换：
- **server**（生产默认）：录音发给本机语音服务，离线 Vosk+Piper。
- **browser**（开发期）：用浏览器原生 `SpeechRecognition` + `speechSynthesis`。**注意**：浏览器原生 ASR 走 Google，国内不可用；且原生不返回性别 → `gender=neutral`。

### 1. 录音 + 自适应 VAD（`voice.ts:208-401`）

Web Audio 直接采 PCM → 降采样 16k 单声道 → 封 WAV（**不引 ffmpeg**，Vosk 直接吃）。

**自适应能量 VAD**（端点检测，判断"人说完了没"）：
- 启动宽限 400ms 测**环境底噪** `noiseFloor`
- 说话阈值 `startTh = max(noiseFloor*2.2, ABS_FLOOR=0.008)`
- 静音阈值 `endTh = max(noiseFloor*1.6, ABS_FLOOR)`
- 连续静音 350ms → 判定"说完"提交；最长 8s 保护；6s 无声音自动取消
- **阈值外置 `.env`**：`NEXT_PUBLIC_VAD_FLOOR / _START_K / _END_K`，现场按环境调，无需改代码（`voice.ts:249-251`）

**踩过的 VAD 坑**（已在代码修复）：原固定阈值 0.008 因 AEC/降噪被刻意关闭（给 Vosk 保真），安静房间本底噪声刚好卡阈值附近 → 停顿检测不到、一直录到最大时长。改自适应底噪后安静/嘈杂都能适配。

### 2. 性别估计（音高法）（`voice.ts:431-470`）

- `estimateF0`：自相关法估计基频 F0（男性 ~85–180Hz，女性 ~165–255Hz）。取录音中间 80% 去首尾静音。
- `estimateGender`：F0<160→male，>175→female，交界区→neutral（保守，避免叫错"先生/女士"）。
- **离线、无额外模型**。优先用本地音高估计的性别，neutral 时回退服务端。

### 3. TTS 双轨（`voice.ts:487-563` + `lib/tts-map.json`）

- **预录优先**：`tts-map.json` 把固定话术文本映射到 `/audio/tts/line_xxx.mp3`（由 `voice-service/gen_tts_audio.py` 用 edge-tts 晓晓女声生成）。命中直接播本地文件 → **发音标准、零合成延迟、离线可用**。
- **Piper 兜底**：未命中的动态文本（如未来接 LLM）回退到 Piper 实时合成（男声华彦）。
- 句子级流式：整段≤50字整段合成；超长按句切，首句即播不等整段。

### 4. 半双工锁（`voice.ts:667-672`）

```ts
function startListening() {
  if (speaking) { pushDebug("讲解中，暂不开麦"); return; } // 防展厅回声/大屏喇叭自激
  ...
}
```
数字人正在讲解时不开麦，避免回声自激。

## 三、后端语音服务（`voice-service/server.py`）

- FastAPI，默认 `127.0.0.1:8000`
- 端点：`/asr`（Vosk）、`/tts`（Piper/SAPI/edge）、`/health`、`/asr-test`
- 引擎由环境变量选：`TTS_BACKEND=piper`、`ASR_BACKEND=vosk`（★交付用）
- 模型：`models/vosk-model-small-cn-0.22`、`models/piper/zh_CN-huayan-medium.onnx`
- 模型单例预加载（`_load_models`），避免每次请求重载省 1~3s

## 四、前端代理（`app/api/voice/*`）

- `route.ts`（ASR）：转发二进制音频到 `{VOICE_SERVICE_URL||127.0.0.1:8000}/asr`
- `tts/route.ts`：转发 `{text, voice}` 到 `/tts`，原样转发 Content-Type 给 `<audio>`
- `health/route.ts`：诊断端点，自动探测 `127.0.0.1` 和 `localhost`，返回不通的真实原因（Windows 下 Node fetch `localhost` 常解析到 IPv6 `::1` 导致超时，故默认优先 `127.0.0.1`）

## 五、技术栈

| 技术 | 用途 |
|------|------|
| Web Audio `ScriptProcessorNode` | 采 PCM、降采样 |
| Vosk（Python） | 离线中文 ASR |
| Piper（Python） | 离线中文 TTS |
| edge-tts（生成预录） | 开发期生成标准女声 mp3 |
| 自相关法 F0 估计 | 离线性别判定 |
| 编辑距离 + 词表纠错 | ASR 错字兜底 |
| FastAPI + Next.js Route Handler | 前后端语音代理 |

## 六、踩的坑（重点！）

1. **VAD 固定阈值在安静房间失效** → 改自适应底噪（见上）。这是语音交互最经典的坑：噪声门限必须随环境动。

2. **Windows `localhost` → IPv6 `::1` 超时**：Node `fetch("localhost")` 解析到 IPv6，而服务只听 IPv4 `127.0.0.1` → 4 秒 abort。默认优先 `127.0.0.1` 解决（`route.ts:11`）。

3. **ASR 误识别吞跨场景跳转**：见 [05-子分区导航](05-子分区导航.md)。靠 `correctAsrText` 近音纠错。

4. **音色不一致**：预录=女声（晓晓），兜底 Piper=男声（华彦）。只有未预录的动态文本会掉男声。若日后接 LLM 动态生成，需统一音色或全量预录。

5. **性别在开发期永远 neutral**：浏览器原生 ASR 不返回性别，所以开发期听不到"先生/女士"差异；要到生产外部 ASR 才有。预录音频虽有三套，开发期只用"您"那套。

6. **半双工锁防自激**：大屏喇叭外放 + 近讲麦，数字人讲解时若同时开麦会回声自激。靠 `speaking` 时不开麦缓解（展厅实测仍建议用近讲麦）。

## 七、学习建议

- **端到端语音系统的分层**：采集(Web Audio) → 端点检测(VAD) → 识别(ASR) → 理解(NLU/规则) → 合成(TTS) → 播放。每一层都可独立替换（本项目 ASR/TTS 都能切 browser/server/piper/vosk）。
- **VAD 为什么难**：端点检测是语音交互的"第一关"，噪声门限、说话/静音判定直接影响体验。理解"自适应阈值"比"固定阈值"稳。
- **离线 vs 在线**：客户机不联网 → 必须用本地模型（Vosk/Piper）。在线方案（Azure/讯飞/edge-tts）音质好但要联网、有隐私/费用问题。选型时要权衡。
- **预录 vs 实时合成**：固定话术预录（音质稳、零延迟、离线）；动态文本只能实时合成（可能有延迟、音色不一致）。这是 TTS 系统的通用 trade-off。
- 延伸：Web Audio API、WAV 格式（44 字节头）、自相关基频估计、Vosk/Piper 模型下载与打包部署。
