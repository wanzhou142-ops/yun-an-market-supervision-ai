# 05 · 子分区导航 + 宣传廊跳模拟药店

> 对应需求：宣传廊/模拟药店有子分区按钮；宣传廊里也能跳到「模拟药店」（平级主场景，不是宣传廊子区）。

## 一、实现流程

### 1. 右侧竖排子分区按钮（`page.tsx:906-915` + `globals.css:324`）

```tsx
{zoneChips(nav).length > 0 && (
  <div className="zone-chips">
    {zoneChips(nav).map((c) => (
      <button className="zone-chip" onClick={() => handleUser(c.kw)}>{c.label}</button>
    ))}
  </div>
)}
```
- `zoneChips(nav)`（`page.tsx:164-177`）只在**宣传廊**（器械/化妆品/药品）和**模拟药店**（传统药房区/新零售模式区）返回按钮；迎宾大厅返回空。
- 点击 = 直接调 `handleUser(kw)`，走和语音**完全相同的** `classify` 意图识别 → 所以按钮和说话等价，只是输入方式不同。
- 布局从「左下竖排」改为**右侧垂直居中**（`right:24px; top:50%; translateY(-50%)`），目的：错开右下角麦克风、避开顶部标题栏，把中下方完整让给数字人。

### 2. 导航意图识别（`page.tsx:336-389` `classify`）

优先级（导航优先于闲聊，避免"去宣传廊？"被当问题）：
1. **主场景跳转** `SCENE_JUMP`（点名目标场景，跨场景直接跳）
2. **返回** 上下文相关（回父级 / 顶层回迎宾）
3. **子分区** `ZONE_KEYWORDS`（取决于当前主场景）
4. **闲聊问候**（含唤醒词"安安"）
5. **模糊兜底** `fuzzyClassify`（编辑距离纠错）

### 3. 宣传廊跳「模拟药店」（关键修复）

**现象**：在宣传廊→化妆品区说"模拟药店"，却跳到宣传廊的"药品区"。

**根因**：`SCENE_JUMP` 里有 `{kw:"模拟药店", next:{scene:"pharmacy"}}`（第 1 步优先），但展厅嘈杂下 Vosk 常把"模拟药店"听成"**药品**" → 第 1 步匹配不到 → 掉进第 3 步子分区 `/(药品|药物)/` → 误跳药品区。

**修复**（`page.tsx:320-327` `correctAsrText` 近音纠错）：
```ts
[/模拟药品/g, "模拟药店"],
[/模型药店/g, "模拟药店"],
[/魔性药店/g, "模拟药店"],
[/模特药店/g, "模拟药店"],
[/模拟药点/g, "模拟药店"],
```
把"模拟X药店"拉回完整"模拟药店"，确保第 1 步命中、跨跳到模拟药店主场景。

**返回逻辑正确**：模拟药店是平级主场景，跳过去后说"返回" → 回**迎宾大厅**（不是回宣传廊），与 `classify` 第 2 步一致，无需额外改。

### 4. 话术/提示补"模拟药店"选项

宣传廊三个子分区话术（`scriptFor`，`page.tsx:143-149`）和底部提示（`hintFor`，`page.tsx:185-189`）都补了"或说**模拟药店**去体验区"，引导用户说全词、降低误判。

## 二、技术栈

| 技术 | 用途 |
|------|------|
| React 条件渲染 + `zoneChips(nav)` | 按状态决定显示哪些按钮 |
| 规则意图识别 `classify` + 优先级 | 导航/选择/闲聊分流 |
| 正则 + 编辑距离 `fuzzyMatch`/`levenshtein` | ASR 错字兜底 |
| 近音纠错 `correctAsrText` | "模拟药品"→"模拟药店" 等 |
| CSS `position: fixed` 右侧竖排 | 按钮布局错开麦克风 |

## 三、踩的坑

1. **ASR 误识别吞掉跨场景跳转**：这是本功能最核心的坑——"模拟药店"是 4 个字，Vosk 小模型在嘈杂展厅常丢"模拟"两字，只剩"药品"就掉进子分区。靠 `correctAsrText` 把"模拟X药店"变体都纠回原词。

2. **主场景正则不能含裸"药房/药店"**：`SCENE_JUMP` 刻意**只用「模拟药店」**，否则在模拟药店说"传统药房区"会被主场景正则先吞掉、永远进不了子分区（代码注释 `page.tsx:246-247` 专门说明）。

3. **按钮和语音要共用同一套 classify**：子分区按钮若单独写跳转逻辑，会和语音分流不一致（说和点的结果不同）。本项目让按钮也调 `handleUser(kw)`，保证"说"和"点"等价。

4. **子分区布局演变**：从左下 → 右侧竖排，纯粹是为了不和右下角麦克风重叠、不挡数字人。布局是受交互元素位置约束倒逼出来的。

## 四、学习建议

- **语音产品的"纠错"是必须的**：ASR 永远不 100% 准，尤其小模型 + 嘈杂环境。前端/后端都要有"近音词表 + 编辑距离"两层兜底。本项目 `correctAsrText`（词表）+ `fuzzyMatch`（编辑距离）是经典组合。
- **状态机的"返回语义"**：导航系统里"返回"的含义依赖上下文（叶子→父级，顶层→首页）。这是树/图状态机的通用设计，和路由（React Router、文件树）的返回逻辑同源。
- **"说"和"点"应等价**：任何带语音的输入系统，按钮最好复用语音的意图入口，避免两套逻辑分叉。
- 延伸：编辑距离（Levenshtein）算法、正则优先级、状态机（有限状态机 FSM）。
