## A 组 · 语音听不准 / 识别对了却不导航

### A1 　点完麦克风立刻说话 → 全程检测不到人声 ★最可能

- **现象**：点麦克风、正常说话，等 6 秒后弹「未检测到说话，请再试一次」。
- **根因**：`lib/voice.ts:243-271`。启动后有 400ms 宽限期专门测环境底噪，用的是这段时间的**平均 RMS**。人点完按钮往往立刻开口，说话声被算进了底噪 → 底噪基准飙高 → 说话阈值（底噪×2.2）跟着飙高 → 后面真说话也过不了线。
- **改法**（三选一，建议第 1 种）
  1. 宽限期内**取最小值**而非平均值：`noiseFloor = min(所有帧 RMS)`，说话声不会拉高基准。
  2. 宽限期缩到 200ms，并只取最低 20% 分位。
  3. 加二次校正：若宽限结束后 1 秒内始终检测不到人声，把 `noiseFloor` 减半重试一次。
- **影响面**：只改 `voice.ts` 内部 20 行，不影响其它模块。
- **验证**：点完按钮**立刻**说「去宣传廊」，调试面板应出现 `VAD: 检测到人声`，且底噪基准打印值应在 0.001~0.01 量级。

### A2 　静音判定 350ms 太短 → 只识别到半句

- **现象**：说「我想去…普法宣传廊」，只识别到「我想去」，然后不导航。
- **根因**：`lib/voice.ts:243` `MIN_SILENCE_MS = 350`。人说话的自然停顿常有 400~700ms，被当成「说完了」。
- **改法**：提到 **600~800ms**。展厅老年访客多，可到 1000ms（小智官方 FAQ 的建议值）。
- **代价**：每轮反应慢 0.3~0.6 秒，展厅场景可接受，比听半句强。
- **验证**：故意在句中停顿一下，看是否还能录完整句（对照 `debug/asr_last.wav`）。

### A3 　8 秒硬截断，且从点按钮就开始计时

- **根因**：`lib/voice.ts:246` `MAX_RECORD_MS = 8000`，计时起点是 `vadStart`（点按钮那一刻），不是开口那一刻。犹豫 3 秒再说话，就只剩 5 秒。
- **改法**：提到 12000ms，并把计时改为「检测到人声之后」才开始算。
- **验证**：点按钮后停 3 秒再说一句长话，应能完整录下。

### A4 　采样率不是 16k 时，服务端重采样又慢又损音质

- **根因**：`lib/voice.ts:232` 请求 `sampleRate: 16000`，但部分声卡/浏览器不支持，会静默 fallback 到 48k。这时 `voice-service/server.py:208-226` 的 `_resample_pcm` 会接手——那是**纯 Python 逐样本线性插值**：
  - 慢：8 秒 48k 音频约 38 万次 Python 循环，实测量级 1~3 秒延迟；
  - 损音质：线性插值降采样**没有抗混叠低通**，会引入混叠失真，直接拉低 Vosk 识别率。
- **前置条件**：先看 **D1**。如果本来就是 16k，这条**不用做**。
- **改法**：在前端用 `OfflineAudioContext` 做带抗混叠的重采样后再发；服务端那段只作兜底。
- **验证**：D1 字节数回到 16k 对应值，且 `debug/asr_last.wav` 听起来不发闷。

### A5 　单字关键词「药」让模糊匹配彻底失效 ★真 bug

- **现象**：在宣传廊场景，**说什么都会跳进「药品专区」**。
- **根因**：`page.tsx:235` 有一条 `{ kw: "药", next: { aspect: "drug" } }`；而 `fuzzyMatch`（`page.tsx:188-205`）对长度 ≤4 的关键词用「编辑距离 ≤1」判定。任意一个汉字与「药」的编辑距离**恒为 1**，所以只要走到模糊兜底，必定命中药品。`unknown` 分支形同虚设。
- **改法**（两处一起改）
  1. `fuzzyMatch` 开头加守卫：`if (keyword.length <= 1) return text.includes(keyword);`
  2. 删掉 `ZONE_KEYWORDS.corridor` 里的单字 `"药"`（保留「药品」「药物」即可）。
- **验证**：宣传廊里说「今天天气不错」，应回引导语而不是跳药品专区。

### A6 　2 字关键词误触发 ★真 bug

- **现象**：说「回来」被当成「返回」跳回迎宾；说「药水」被当成「去药店」。
- **根因**：同 `fuzzyMatch` 的编辑距离 ≤1 规则。`NAV_KEYWORDS` 里的「返回/走廊/展区/展览/科普/药店/药房」全是 2 字词，任何差一个字的词都会命中。
- **改法**：按长度分档——**2 字词要求精确包含（距离 0）**，3 字及以上才允许距离 1。
- **验证**：说「药水多少钱」不应跳转场景。

### A7 　叫名字的判定压过了导航 ★真 bug

- **现象**：说「安安，带我去宣传廊」→ 只回问候，**不切场景**。
- **根因**：`page.tsx:297`，`t.includes("安安")` 的判定写在所有导航判定**之前**，直接 return `chat`。
- **改法**：分类前先把名字从文本里剥掉（`t.replace(/安安/g, "")`），再走正常流程；剥离后如果剩余内容为空，才判为纯问候。
- **验证**：「安安，去药店」应正常切到模拟药店。

### A8 　「药房」吃掉子分区，进不去传统药房区 ★真 bug

- **现象**：在模拟药店里说「传统**药房**区」，画面重置回药店主场景，进不去传统区。
- **根因**：`page.tsx:302` 主场景正则 `/(药店|药房|模拟药店|药房区)/` 排在子分区判定（`page.tsx:316-320`）之前，且不判断「是不是已经在这个场景了」。
- **改法**（两处）
  1. 主场景导航加守卫：**已经在目标场景时不重置**（`if (st.scene !== "pharmacy")` 才切）。
  2. 把子分区判定提到主场景判定之前——当前场景内的选择应优先于跨场景跳转。
- **验证**：药店里说「传统药房区」进 traditional；说「宣传廊」仍能正常跨场景跳走。

### A9 　纠错表误伤

- **根因**：`page.tsx:272` 把「期限」无条件替换成「器械」。用户问「保质期限多久」会被改成「保质器械多久」。
- **改法**：这条纠错只在 `scene === "corridor"` 时生效。
- **优先级**：低，等前面改完再说。

## B 组 · 声音相关问题

### B1 　两段语音叠着响 ★真 bug

- **现象**：连续点两个分区按钮（或 AI 还在说话时又输入），两条语音同时播放。
- **根因**：`lib/voice.ts:490-518`。`speak()` 命中预录 mp3 时，直接 `new Audio()` 就播，**完全不检查也不停止 `tts.currentEl`**。走 Piper 分支时虽然不会叠音，但队列被覆盖，逻辑也是乱的。
- **改法**：`speak()` 第一行先调 `this.cancel()`（停当前 + 清队列），再开始新的播放。
- **验证**：快速连点「器械专区」「化妆品专区」，应只听到后一句。

### B2 　AI 说话时还能开麦 → 外接音响回声自激 ★现场高风险

- **现象**：办公室小音量不明显；展厅外放大音量时，机器会把自己说的话识别成访客提问，自问自答。
- **根因**：`page.tsx:553` `startListening()` 不检查 `speaking` 状态。文档里写的「靠半双工规避回声」这道锁**代码里根本没有**。
- **改法**（两层都要）
  1. `speaking === true` 时麦克风按钮置灰不可点；
  2. 点麦克风时先 `voiceRef.current.cancel()` 掐掉正在播的 TTS，再开录。
- **验证**：AI 播报中点麦克风，按钮应无响应或先停播再录音。

### B3 　TTS 失败是静默的，排错没线索

- **根因**：`lib/voice.ts:179` 和 `:201` 只有 `console.error`，调试面板看不到。Piper 合成失败时前端表现就是「什么都没发生」。
- **改法**：给 `speak()` 加一个 `onDebug` 回调，接到 `page.tsx` 的 `pushDebug`，让 TTS 失败、回退 Piper、播放异常都显示在调试面板上。
- **价值**：这条本身不修 bug，但后面所有声音问题的排查都靠它。**建议优先做。**

### B4 　中性性别念出「抱歉，您，我是安安」

- **现象**：没识别出性别时，话术是「抱歉，**您**，我是安安…」「欢迎来到普法宣传廊，**您**。」「这里是模拟药店体验区，**您**。」——读出来很别扭。
- **根因**：`page.tsx:109`（guidanceLine）、`:128`、`:138`（scriptFor）直接拼 `genderWord(g)`，而 `genderWord("neutral")` 返回「您」。`greetingLine` 已经做了 neutral 特判，这三处漏了。
- **改法**：抽一个 `addressPhrase(g)` —— male→「，先生」/ female→「，女士」/ neutral→**空串**，三处统一改用它。
- **⚠️ 连带工作**：这三句已经录进预录音频（`line_010/013/021.mp3`）。改文案后 `tts-map.json` 的 key 会对不上，必须重跑 `voice-service/gen_tts_audio.py` 重新生成，否则会静默回退到 Piper 实时合成（发音变差、有延迟）。
- **优先级**：单独一批做，别和其它改动混在一起。

### B5 　返回视频模式时 TTS 不停，和视频原声打架

- **根因**：`page.tsx:452` `exitToVideo()` 恢复了视频原声，但**没有停掉正在播的数字人语音**；`switchScene()`（`:393`）同样没停。
- **改法**：两个函数里都加一句 `voiceRef.current?.cancel()`。
- **验证**：数字人说话中途点「返回视频」，语音应立刻停，只剩视频声。

### B6 　麦克风按钮没有健康门禁

- **根因**：`page.tsx:415-433` 健康检查只在页面加载时跑一次，结果只打日志。语音服务挂掉后按钮照样能点，点了才报错。
- **改法**：把 `reachable` 存进 state，不可达时按钮置灰并显示「语音服务未启动」。
- **优先级**：中。现场稳定性相关，进场前要有。

### B7 　ENABLE_TTS 是假开关

- **根因**：`page.tsx:13` 硬编码常量 `true`，和 `.env.local` 里的 `ENABLE_TTS` 没有任何关联。
- **改法**：要么接到环境变量（需改成 `NEXT_PUBLIC_` 前缀），要么删掉 `.env` 里那行避免误导。
- **优先级**：最低。
