## 1. 设计目标与原则

1. **主动引导式**：数字人先问，访客短答或说完整句均可（"我想去宣传廊""宣传廊""带我去药品区"都接受）。
2. **触摸保底 + 语音增强**：屏幕按钮/标签永远可达；语音是加分项，不是唯一入口。
3. **手持近讲麦 + 按钮触发**：访客**按屏幕按钮**唤醒，再对手持麦说话。这天然规避了"远场免唤醒"的噪声误触发和回声自激，是嘈杂展厅里最稳的形态。
4. **性别自适应**：除迎宾大厅外，每句问候按访客音高判先生/女士；判不出 → 中性兜底。
5. **流程必须贯通**：迎宾 ↔ 宣传廊 ↔ 模拟药店 三向可达，含子分区与返回。

## 2. 设备与部署前提（已确认）

- 一台电脑同时连**大屏**和**麦克风**（浏览器与 voice-service 同机，`localhost` 收麦成立）。
- 麦克风为**手持近讲麦**（访客/工作人员手持，离嘴 5–15cm 说话）。**不依赖远场阵列麦**。
- 视频模式**一直播**，无人交互不中断；按按钮才切入交互。
- 语音后端（`voice-service` + Vosk + Piper）必须随部署包一同发出（现有 `deploy/` 缺此部分，见第 9 节）。

## 3. 完整对话树

```
[视频模式] ── 一直播背景视频，无交互不中断
    │ 访客按【屏幕按钮】唤醒
    ▼
[迎宾大厅·交互]  (gender: 无，永远中性)
  安安:"您好，我是安安，云安市场监管普法迎宾助手，
        请问您想参观宣传廊，还是模拟药店？"
    │ 访客说"我想去宣传廊"(任意同义) → 拿音高估性别 g → 跳[宣传廊]
    │ 访客说"模拟药店"(任意同义)     → 拿音高估性别 g → 跳[模拟药店]
    │ 访客答非所问/无关               → "抱歉，您想先去宣传廊还是模拟药店？"(中性)
    ▼
[宣传廊·交互]  (gender: g)
  安安:"{先生/女士/中性}，欢迎来到普法宣传廊，
        您想重点了解哪方面？可以说器械、化妆品，或者药品。"
    │ 访客说"药品"        → 进[叶子·药品]
    │ 访客说"模拟药店"    → 跨跳[模拟药店]
    │ 访客说"返回/回迎宾大厅" → [迎宾大厅]
    ▼
[叶子·器械 / 化妆品 / 药品]  (gender: g)
  安安(中性播内容): "{器械/化妆品/药品 固定内容}"
  安安:"{先生/女士/中性}，{内容}介绍到这里。还想了解其他的吗？或者说返回。"
    │ 访客"返回"           → 回[宣传廊]
    │ 访客"化妆品/器械"    → 播对应叶子
    │ 访客"模拟药店"       → 跨跳[模拟药店]
    │ 访客"回迎宾大厅/回首页" → [迎宾大厅]
    ▼ (无操作 35s) → [视频模式]
[模拟药店·交互]  (gender: g)   [子分区待客户确认，先放"传统药房区"做通]
  安安:"{先生/女士/中性}，欢迎来到模拟药店，
        您想了解哪方面？可以说传统药房区[，或其他待定分区]。"
    │ 访客说子分区名       → 播对应内容
    │ 访客说"宣传廊"       → 跨跳[宣传廊]
    │ 访客说"返回"         → 回[模拟药店]父级(=自身交互节点)
    │ 访客说"回迎宾大厅"    → [迎宾大厅]
    ▼ (无操作 35s) → [视频模式]
```

### 返回语义速查表

| 访客说 | 在[宣传廊叶子] | 在[宣传廊] | 在[模拟药店叶子] | 在[模拟药店] |
|---|---|---|---|---|
| "返回" | → 宣传廊 | → 迎宾大厅 | → 模拟药店 | → 迎宾大厅* |
| "回迎宾大厅/回首页" | → 迎宾大厅 | → 迎宾大厅 | → 迎宾大厅 | → 迎宾大厅 |
| "模拟药店" | → 模拟药店 | (原地) | — | — |
| "宣传廊" | → 宣传廊 | — | → 宣传廊 | (原地) |

> *说明：模拟药店当前交互节点即其顶层，无独立"父级场景"，故其"返回"等价于回迎宾大厅；若客户后续给模拟药店加子分区，"返回"应回模拟药店交互节点（与宣传廊一致）。代码按"返回=回父级节点"统一实现即可。

## 4. 节点话术与预录方案

### 4.1 预录策略（沿用现有 `tts-map.json` + 21 条 mp3 机制）

动态变量空间极小：**性别 3 态 × 场景问候**。沿用现有机制——`tts-map.json` 按 line ID 查预录 mp3；key 缺失自动回退 Piper 实时合成（现有兜底不变）。

### 4.2 各节点话术与预录文件规划

| 节点 | 话术 | 性别变体 | 预录 key 示例 | 文件数 |
|---|---|---|---|---|
| 迎宾大厅·问候 | "您好，我是安安，云安市场监管普法迎宾助手，请问您想参观宣传廊，还是模拟药店？" | 仅中性 | `welcome_greet` | 1 |
| 迎宾·答非所问 | "抱歉，您想先去宣传廊还是模拟药店？" | 仅中性 | `welcome_fallback` | 1 |
| 宣传廊·问候 | "{先生/女士/中性}，欢迎来到普法宣传廊，您想重点了解哪方面？可以说器械、化妆品，或者药品。" | 3 态 | `corridor_greet_male/female/neutral` | 3 |
| 叶子·内容(器械/化妆品/药品) | 各分区固定科普内容 | 中性(内容) | `leaf_device/content_cosmetics/content_drug` | 3 |
| 叶子·结束追问 | "{先生/女士/中性}，{内容}介绍到这里。还想了解其他的吗？或者说返回。" | 3 态 | `leaf_ask_male/female/neutral` | 3 |
| 模拟药店·问候 | "{先生/女士/中性}，欢迎来到模拟药店，您想了解哪方面？可以说传统药房区[，或其他待定分区]。" | 3 态 | `pharmacy_greet_male/female/neutral` | 3 |
| 模拟药店·子分区内容 | 待客户定(先放传统药房区占位) | 中性 | `pharmacy_trad_content` | 1+ |

**合计约 15 条 mp3**（含中性兜底）。改完 `tts-map.json` 的 key 后**必须重跑 `gen_tts_audio.py`**（否则静默回退 Piper，音色变差带延迟）。

### 4.3 性别选择运行时逻辑

```
准备说话时：
  if 节点 == 迎宾大厅: 用中性 key（welcome_*）
  else:
    g = 上次访客语音估出的性别   // estimateGender() 自相关法
    if g == 'male'  : 用 *_male
    elif g == 'female': 用 *_female
    else (neutral)  : 用 *_neutral   // 绝不说"这位访客"
```

> 关键点：**迎宾大厅是第一句，之前没人说话，没有音高样本 → 强制中性**；从宣传廊起，访客在迎宾大厅答"我想去宣传廊"那句话已拿到音高，后续节点都能用。

## 5. 意图识别规则（`classify` / `fuzzyMatch` 改造方向）

> 以下为**设计规则**，对应代码改动点见第 9 节。当前 `classify()` 是命令式+关键词，需补"短答/跨场景点名"能力。

### 5.1 意图优先级（从高到低）

1. **返回/首页**：含「返回」「回去」「回首页」「回迎宾大厅」→ 按第 3 节返回语义表路由。
2. **点名目标场景**（跨跳）：含「宣传廊」「模拟药店」「迎宾大厅/首页」→ 直接跳该场景（**不要求带"去"字**，"宣传廊"单独一句也跳）。
3. **进入子分区**：含「器械」「化妆品」「药品」「传统药房区」→ 进对应叶子。
4. **唤醒词（可选）**：含「安安」→ 视为唤醒（按钮已唤醒时此条可忽略）。
5. **兜底**：ASR 空或都不匹配 → "抱歉，没听清，请再说一遍，或点屏幕选择"（并给可点场景按钮）。

### 5.2 必须修掉的现存 bug（影响本流程）

- **叫名字优先于导航**：当前 `page.tsx` 叫"安安"判断排在导航前，导致"安安，带我去宣传廊"只回问候不切场景 → 改为：唤醒词只用于"从视频模式切入交互"，切入后不再拦截导航。
- **单字「药」误判**：`ZONE_KEYWORDS.corridor` 含单字"药"，模糊匹配对 ≤4 字用编辑距离≤1，任意汉字与"药"距离恒为 1 → 宣传廊里几乎任何输入都跳药品专区 → 去掉单字关键词，只用 ≥2 字词组。
- **主场景正则含「药房」**：模拟药店里说"传统药房区"会被主场景正则先吃掉重置 → 调整正则作用域，仅在特定上下文生效。

## 6. 性别判断规则

- 实现：`lib/voice.ts` 的 `estimateGender(merged, ctxRate)`（自相关法测基频）。

## 7. 空闲超时

- 任何交互节点 **35 秒** 无有效操作/无新语音 → 自动切回[视频模式]（停止 ASR 收听、TTS 播完即停）。
- 计时在"数字人说完 + 开始等待访客输入"时启动；访客说话/按键即重置。

## 8. 噪声应对（展厅吵）

展厅嘈杂是已知环境，靠以下组合化解（**不依赖远场阵列麦**）：

1. **手持近讲麦**：声源离麦 5–15cm， ambient 噪声被物理衰减，是最有效的抗噪手段。
2. **按钮触发而非语音唤醒**：没有"一直在听"，从根上消除人群噪声误唤醒。
3. **半双工锁（必做）**：TTS 播报期间强制禁麦，防展厅回声 + 大屏喇叭自激（当前代码未实现，见第 9 节）。
4. **首启自动校准 VAD**：部署首次启动测现场底噪，阈值 = 底噪 × K（而非写死 `ABS_FLOOR`），并外置到 `.env` 可调（当前写死在 `voice.ts`）。
5. **关键词兜底导航**：即使"安安"被噪声淹没，句子含场景词仍触发跳转（第 5.1 节）。
6. **轻度降噪（可选）**：如近讲仍不稳，可加 WebRTC NS/AGC，但手持近讲通常已够。
