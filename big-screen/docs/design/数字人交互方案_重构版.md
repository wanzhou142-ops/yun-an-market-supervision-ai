# 数字人交互方案（重构版）

> 整理时间：2026-07-29
> 状态：方向已与经理 / 用户对齐；**双模式交互（视频模式默认 + 交互模式）已落地**，`page.tsx` 已实现状态机 + 场景/子分区切换 + 缺片回退父场景。P0 迎宾视频接入 / P1 表现层改造 / P2 编排层核心 已完成；P3 分区视频 / P4 语音模型 / P5 部署包更新 待客户素材与模型。
> 背景：原 Dify 方向被判断为"把 Dify 当成了数字人本身"——本文给出修正后的分层架构与落地规格。

## 0. 一句话结论

数字人方案 = **表现层（大屏前端） + 编排层（新建大脑） + 知识层（Dify 退为知识 API）**。
Dify 不推倒，只归位成"被调用的 RAG 知识引擎"；缺的那块"导览大脑"新建为**编排层**，负责状态机、意图识别、视频切换。

## 1. 需求回顾：原方案"数字人交互方案"

大屏 + 音响的**语音驱动导览**，分四区，每区交互方式不同：

| 区域 | 内容 | 交互方式 |
|---|---|---|
| 迎宾大厅 | 数字人欢迎、播放基地介绍视频、询问去宣传廊还是模拟药店 | 语音合成 + 小动画 + 背景切换 |
| 宣传廊 | 数字人介绍、询问进器械/化妆品/药品区，各区分区介绍 + 访客可打断交互 | 语音合成 + 小动画 + 视频 + 生成画面 |
| 模拟药店 | 数字人介绍、选传统药房/新零售区，比对违法违规现象 | 图片切换 + 语音识别 + 智能体比对 |
| 控制 | 遥控器 + 麦克风收音 | — |

原架构中"智能体核心"是大脑（意图 / 决策 / 流程编排），**Dify 只是它"被调用的知识库引擎"**。

## 2. 当前 Dify 方向的问题诊断（3 处偏差）

1. **主体错位**：Dify 是文本 RAG 问答工具，不是数字人；我们把它当成了数字人方案的 80%，但数字人的"灵魂"（语音、表演、导览状态机、大屏控制）都在 Dify 之外。
2. **语音核心被边缘化**：原方案以"说 + 听"驱动，我们做成文字聊天、语音一直 defer 给客户。
3. **缺导览流程**：三区是 3 个靠 URL 平行切换的独立聊天框，没有"迎宾 → 问 → 切换 → 宣传廊 → 选分区"的连续体验。

## 3. 重构大方向：三层架构

- **表现层（复用现有 Next.js 大屏前端）**：视频背景 + 数字人 overlay + 对话框 + TTS / ASR。
- **编排层（新建，核心）**：导览状态机 + 意图识别 + 场景 / 视频切换决策 + 调用 Dify。
- **知识层（Dify，已有，不推倒）**：RAG 知识库（4 部法），只答事实问答，被编排层调用。

数据流：用户输入 → 表现层 → 编排层（意图识别 → 状态机 → 动作执行）→ 事实问答才调 Dify → 编排层 → 表现层（播放 / 朗读 / 切视频）。

## 4. 视频角色定位

- 经理确认：客户提供的视频是**数字人"播放的内容 / 切换对象"**（迎宾宣传视频 + 宣传廊各分区宣传片 + 模拟药店内容），**不是数字人本身**。
- 我们**不生产视频**（除非二期 AI 生成），只做：
  1. 把视频接进流程对应插槽；
  2. 让数字人对话驱动"切到哪、播哪段"；
  3. Dify 继续管事实问答。
- 数字人形象：维持 SVG overlay（经理未要求换真数字人视频），后续可升级。

## 5. 编排层核心设计

### 5.1 状态机

```
state = {
  scene:  'welcome' | 'corridor' | 'pharmacy',
  aspect: null | 'device' | 'cosmetic' | 'drug',   // 仅 corridor
  zone:   null | 'traditional' | 'newretail'        // 仅 pharmacy
}
```

状态与转移：
- WELCOME --[去宣传廊]--> CORRIDOR；--[去药店]--> PHARMACY
- CORRIDOR --[了解器械 / 化妆品 / 药品]--> 设 aspect + 播对应片
- PHARMACY --[传统 / 新零售]--> 设 zone
- 任意 --[返回 / 迎宾]--> WELCOME（清空子状态）
- 任意 --[事实问答]--> 状态不变，调 Dify

### 5.2 意图识别（v1 规则关键词，不调额外 LLM）

判定顺序（关键：**导航 / 选择优先于事实问答**）：
1. 先判"是否问句"：含 `？` 或 `什么 / 怎么 / 哪些 / 如何 / 是否 / 为什么 / 能不能` → `FACTUAL_Q`，路由 Dify（即使含"药品"也走问答，不会误切）。
2. 否则匹配导航 / 选择关键词：去宣传廊 → CORRIDOR；去药店 → PHARMACY；返回 → WELCOME；了解器械 / 化妆品 / 药品 → 设 aspect；传统 / 新零售 → 设 zone。
3. 闲聊（你好 / 谢谢 / 你是谁）→ 引导话术。
4. 兜底 UNKNOWN → 数字人重复当前状态的问题。

后续可把 1 / 2 步换成 LLM 意图分类，接口不变。

### 5.3 输出适配

生成对话气泡 + TTS 文本（自动去 OS 括号）+ 数字人动画指令（放大 / 绿光 / 口型）。

| 状态 | 进入视频（优先播放） | 数字人引导语（仅用户主动输入后才说） | 引导提问 | 识别意图 |
|---|---|---|---|---|
| WELCOME | welcome.mp4 | （待命，不主动说）用户输入后才说：你好，我是云安市场监管普法迎宾助手… | 想参观宣传廊还是模拟药店？ | 宣传廊→CORRIDOR；药店→PHARMACY；问答→Dify；未知→重复 |
| CORRIDOR | corridor-overview.mp4（选分区后播对应片） | （待命）用户输入后说：欢迎来到普法宣传廊… | 想了解器械、化妆品还是药品？ | 器械/化妆品/药品→设 aspect 播片；返回→WELCOME；问答→Dify |
| CORRIDOR+分区 | corridor-device / cosmetic / drug.mp4 | （待命）用户输入后简介该区 | 还想了解其他分区吗？说"返回"回迎宾 | 跨分区→切片；返回→WELCOME；问答→Dify |
| PHARMACY | pharmacy.mp4 | （待命）用户输入后说：这里是模拟药店体验区 | 看传统药房区还是新零售模式区？ | 传统/新零售→设 zone；问答→Dify；返回→WELCOME |
| PHARMACY+分区 | pharmacy-traditional / newretail.mp4 | （待命）用户输入后简介该区 | （可抛违法违规比对问题） | 返回→WELCOME；问答→Dify |

> **交互节奏（v1 已落地）**：双模式 + 场景标签仅在数字人（交互）界面显示——
> - **视频模式（默认）**：进入场景先播放**带原声**视频（浏览器禁止带声自动播放时，点画面任意处即解锁；展机用 Chrome 启动参数可免点击直接带声）。屏幕**仅右下角一个「开始互动」按钮**（模拟遥控 / 语音控制输入），**不显示顶栏、不能切场景**；数字人不出面、不讲话。
> - **交互模式**：点击「开始互动」后数字人出现并说开场引导，进入可对话状态（打字 / 点麦克风 / 顶部 tab 切换场景）。此时**顶栏（标题 + 三个场景标签）显示在界面顶端**，背景视频自动**静音**，只作数字人背景，避免与 TTS 朗读冲突。「返回视频」按钮在**左下角**，可收起回到纯净视频。
> - 视频层两种模式始终常驻播放、不重启；按钮点击即「用户主动交互」，符合"先播视频、等有人交互才交互"。
>
> **声音策略**：视频原声（视频模式）与数字人 TTS（交互模式）错峰——视频模式出视频声、交互模式出数字人声，互不打架。展机部署（`deploy/start.cjs`）已优先调用 Chrome 并加 `--autoplay-policy=no-user-gesture-required`，保证开机即带声自动播放；若客户机器无 Chrome 则回退默认浏览器（自动带声可能受限，需手动允许）。
